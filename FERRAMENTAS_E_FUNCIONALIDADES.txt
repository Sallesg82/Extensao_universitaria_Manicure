================================================================================
           BEAUTYFLOW — EXTENSÃO UNIVERSITÁRIA: SALÃO & MANICURE
              MAPA COMPLETO DE FERRAMENTAS E SUAS FUNCIONALIDADES
================================================================================

Este documento descreve de forma minuciosa todas as ferramentas, tecnologias,
módulos, componentes, integrações, scripts e funcionalidades presentes no
ecossistema completo do projeto BeautyFlow.

--------------------------------------------------------------------------------
1. VISÃO GERAL DO ECOSSISTEMA
--------------------------------------------------------------------------------
O BeautyFlow é uma plataforma integrada de gestão e atendimento para salões de
beleza e estética, composta por 3 pilares principais:

1. CRM BeautyFlow (Painel de Gestão Administrativa e Financeira)
2. Beatriz Gomes Studio (Portal Web responsivo para autoatendimento dos clientes)
3. Infraestrutura & DevOps (Hub TUI de Gestão, Docker Compose e Banco de Dados)

================================================================================
2. STACK TECNOLÓGICO E BIBLIOTECAS (FERRAMENTAS TÉCNICAS)
================================================================================

[ BACKEND ]
• Python 3.11 / 3.14: Linguagem principal da API backend.
• Flask (3.0.3): Microframework web utilizado para construir a API RESTful e
  servir as rotas estáticas do CRM.
• Flask-CORS (4.0.1): Middleware para controle de Cross-Origin Resource Sharing,
  permitindo comunicação segura entre frontends e a API.
• Flask-SocketIO (5.3.6) & python-socketio / python-engineio: Gerenciador de
  WebSockets para sincronização em tempo real (mudanças de dados, criação e
  atualização de agendamentos, clientes e transações sem recarregar a página).
• Psycopg 3 (psycopg[binary] 3.1.18 & psycopg-pool 3.2.1): Driver PostgreSQL
  moderno com pool de conexões ativo (ConnectionPool) para alta performance.
• Werkzeug Security: Sistema de hash e validação segura de senhas (PBKDF2/SHA256).
• Google API Client, google-auth-oauthlib, google-auth, requests-oauthlib:
  Biblioteca oficial do Google para autenticação OAuth 2.0 e manipulação de
  eventos no Google Calendar.
• Requests (2.32.3): Cliente HTTP para envio de webhooks ao n8n e integrações.
• Python-Dotenv (1.0.1): Carregador de variáveis de ambiente a partir de .env.
• Gunicorn / Werkzeug Server: Servidores de aplicação WSGI para execução.

[ FRONTEND — CRM BEAUTYFLOW ]
• HTML5 Semântico & CSS3 Puro (Vanilla): Interface SPA completa, modular e veloz.
• JavaScript ES6+ (Vanilla): Lógica de aplicação reativa com fetch, navegação por
  hash, renderização dinâmica de SVG (gráficos) e manipuladores DOM.
• Socket.IO Client (4.7.5 via CDN): Comunicação WebSocket bidirecional em tempo real.
• Google Fonts (DM Serif Display & DM Sans): Tipografia moderna e elegante.

[ FRONTEND — PORTAL DE AGENDAMENTO CLIENTE ]
• React 19: Biblioteca para construção de interfaces reativas baseadas em componentes.
• Vite 8: Bundler e servidor de desenvolvimento ultra-rápido.
• Tailwind CSS 4 & @tailwindcss/vite: Framework utilitário de estilização moderna.
• Socket.IO Client (4.8.3): Recepção de eventos realtime do backend.
• ESLint 10: Linter e padronizador de código estático.

[ BANCO DE DADOS & ARMAZENAMENTO ]
• PostgreSQL 16 (Local via Docker ou Cloud via Supabase): Banco de dados relacional.
• SQL Nativo + Views + Triggers + Índices: Consultas otimizadas, agregação de
  dados e integridade referencial com ON DELETE SET NULL.

[ DEVOPS & DEPLOY ]
• Docker & Docker Compose: Conteinerização isolada de banco, CRM e Agendamento.
• Nginx Alpine: Servidor web de alta performance para arquivos estáticos do React.
• Bash & Batch Scripts: Automação multiplataforma para Linux, macOS e Windows.

3. CRM BEAUTYFLOW — MÓDULOS E FUNCIONALIDADES DO PAINEL GESTOR

seguintes ferramentas e telas:

3.1. MÓDULO DE AUTENTICAÇÃO E CONTROLE DE ACESSO
--------------------------------------------------------------------------------
• Login seguro por e-mail e senha com validação via hash criptográfico.
• Cadastro de novos administradores/usuários caso o banco esteja vazio.
• Persistência de sessão no LocalStorage do navegador.
• Logout seguro com limpeza de cache e sessão.

--------------------------------------------------------------------------------
• Card "Receita Hoje": Total faturado no dia atual com contagem de atendimentos.

--------------------------------------------------------------------------------

5. FERRAMENTAS DE INFRAESTRUTURA, DEPLOY E DEVOPS
================================================================================

O diretório `Aplicativos/instalacao/` contém o ecossistema de implantação:

5.1. DOCKER COMPOSE (`docker-compose.yml`)
--------------------------------------------------------------------------------
• Orquestração de 3 contêineres essenciais conectados na rede `beautyflow-net`:
  1. `beautyflow-postgres`: PostgreSQL 16 Alpine com volume persistente
     `postgres_data`, inicialização automática do arquivo `schema.sql` e
     healthcheck via `pg_isready` a cada 3 segundos.
  2. `beautyflow-crm`: Backend Flask + SPA do CRM na porta 3001, aguarda o
     healthcheck saudável do banco de dados antes de inicializar.
  3. `beautyflow-agendamento`: Frontend React servido via Nginx na porta 5173
     (mapeado para porta 80 interna), com build-arg `VITE_API_URL` configurável.

5.2. HUB TUI DE INSTALAÇÃO, MANUTENÇÃO E GESTÃO
--------------------------------------------------------------------------------
• `install.sh` (Linux / macOS) & `install.bat` (Windows):
  - Interface Interativa TUI em Terminal: estética elegante com caracteres de
    desenho de caixa (`┌─┐│└┘`), indicadores de status em tempo real (`[ ONLINE ]`
    e `[ OFFLINE ]`), sem uso de emojis.
  - Opção 1 — Instalação Completa: detecção de dependências, resolução de conflitos
    de portas (5432, 3001, 5173), autodetecção do IP de rede para acesso mobile
    e carga de sementes no banco.
  - Opção 2 — Iniciar Serviços: sobe os 3 contêineres em background.
  - Opção 3 — Parar Serviços: pausa a stack com segurança sem perda de dados.
  - Opção 4 — Reiniciar Serviços: reinicia os contêineres e valida healthchecks.
  - Opção 5 — Atualizar Plataforma: sincronização Git opcional e rebuild completo
    mantendo intacto o volume persistente do banco de dados.
  - Opção 6 — Submenu de Banco de Dados:
      * [1] Criar Backup Completo (`pg_dump` com timestamp em `backups/`).
      * [2] Restaurar Backup a partir de arquivo `.sql`.
      * [3] Listar Backups Existentes com datas e tamanhos.
      * [4] Testar Conexão e Integridade das Tabelas.
      * [5] Resetar Banco (recriação limpa com sementes padrão via `schema.sql`).
  - Opção 7 — Configuração de Rede & IP: ajusta a URL da API e recompila o portal.
  - Opção 8 — Visualização de Logs: streaming em tempo real geral ou filtrado.
  - Opção 9 — Redefinir Senha do Administrador: troca a senha do usuário `admin`.
  - Opção 10 — Desinstalar: limpeza de ambiente protegida por palavra de segurança.

• Scripts Rápidos de 1 Clique (Dia a Dia):
  - `start.sh` (Linux) / `start.bat` (Windows): inicia a plataforma com 1 comando.
  - `stop.sh` (Linux) / `stop.bat` (Windows): desliga a plataforma preservando dados.

• `Dockerfile.crm`:
  - Build baseado em `python:3.11-slim`, instalação de requirements e execução.
  - Healthcheck ativo via consulta HTTP na porta 3001.

• `Dockerfile.agendamento`:
  - Build multi-stage: Node.js 20-alpine para compilar a aplicação React Vite,
    seguido de Nginx Alpine com SPA Fallback (`try_files $uri $uri/ /index.html;`).
  - Healthcheck ativo via `wget` na porta 80.

• `tutorial.md`:
  - Manual operacional completo do hub interativo e documentação de deploy.

6. MODELO DE DADOS (TABELAS, VIEWS E REGRAS DE NEGÓCIO)
================================================================================

6.1. TABELAS DO BANCO DE DADOS
--------------------------------------------------------------------------------
• `clients`:
  - `id` (Serial PK), `name` (Texto), `phone` (Texto), `email` (Texto),
  - `avatar_initials`, `avatar_bg`, `avatar_color`, `cpf`, `notes`,
  - `status` (regular, frequente, novo, inativo, caloteiro),
  - `created_at`, `updated_at`.
• `appointments`:
  - `id` (Serial PK), `client_id` (FK -> clients.id ON DELETE SET NULL),
  - `service`, `appointment_date`, `appointment_time`,
  - `status` (pending, confirmed, done, cancelled),
  - `payment_status` (paid, unpaid),
  - `price`, `duration`, `notes`, `google_event_id`, `google_html_link`,
  - `created_at`, `updated_at`.
• `services`:
  - `id` (Serial PK), `name` (Texto UNIQUE), `duration` (Minutos),
  - `buffer` (Minutos de margem), `price` (Valor R$), `color` (Hexadecimal),
  - `created_at`.
• `transactions`:
  - `id` (Serial PK), `type` (income / expense), `description`, `amount`,
  - `category`, `payment_method`, `date`,
  - `appointment_id` (FK -> appointments.id ON DELETE SET NULL),
  - `client_id` (FK -> clients.id ON DELETE SET NULL),
  - `client_name` (Texto persistente), `service` (Texto persistente),
  - `created_at`.
• `settings`:
  - `key` (Texto PK), `value` (Texto).
  - Armazena: `meta_mensal`, credenciais Google, parâmetros n8n, regras de
    notificação, configurações visuais, dados da empresa e categorias de despesa.
• `business_hours`:
  - `id` (Serial PK), `day` (segunda a domingo UNIQUE), `open` (ex: '08:00'),
  - `close` (ex: '18:00'), `closed` (Booleano), `created_at`, `updated_at`.
• `notifications`:
  - `id` (Serial PK), `type`, `title`, `message`, `related_id`, `related_type`,
  - `read` (Booleano), `created_at`.
• `integrations`:
  - `id` (Serial PK), `name`, `type` (webhook, n8n, google_calendar),
  - `config` (JSONB), `enabled` (Booleano), `created_at`, `updated_at`.
• `users`:
  - `id` (Serial PK), `name`, `email` (UNIQUE), `phone`, `password_hash`,
  - `role` (admin), `created_at`.

6.2. VIEWS E FUNÇÕES SQL
--------------------------------------------------------------------------------
• `v_clients`: Agrega total de visitas concluídas, total gasto acumulado e data
  da última visita de cada cliente.
• `v_month_stats`: Consolida faturamento mensal de transações de entrada, total
  de despesas, quantidade de agendamentos e clientes únicos no mês atual.
• `v_daily_stats`: Agrupamento diário de receita e despesas do mês corrente.
• `trigger_set_updated_at`: Gatilho PL/pgSQL que atualiza a coluna `updated_at`
  automaticamente antes de qualquer operação de UPDATE nas tabelas monitoradas.

7. MAPEAMENTO COMPLETO DE ROTAS DA API REST
================================================================================

[ CLIENTES — /api/clients ]
• GET    /api/clients/          -> Listar clientes (com filtros ?search= e ?status=)
• GET    /api/clients/<id>      -> Detalhes de um cliente (histórico e serviços)
• POST   /api/clients/          -> Cadastrar nova cliente
• PUT    /api/clients/<id>      -> Atualizar dados da cliente
• DELETE /api/clients/<id>      -> Excluir cliente

[ AGENDAMENTOS — /api/appointments ]
• GET    /api/appointments/     -> Listar agendamentos (?date=, ?date_from=, ?date_to=, ?status=)
• GET    /api/appointments/<id> -> Obter agendamento por ID
• POST   /api/appointments/     -> Criar agendamento (valida horário, dispara n8n/Google/Socket)
• PUT    /api/appointments/<id> -> Atualizar agendamento (sincroniza receita financeira)
• DELETE /api/appointments/<id> -> Cancelar/Excluir agendamento

8. EVENTOS WEBSOCKET (TEMPO REAL)
================================================================================
O servidor Flask-SocketIO emite e escuta eventos em tempo real para atualização
instantânea entre telas e dispositivos:

• `client:created`, `client:updated`, `client:deleted`: Disparados quando clientes são manipulados.
• `appointment:created`, `appointment:updated`, `appointment:deleted`: Disparados em agendamentos.
• `service:changed`: Disparado quando serviços são criados, editados ou removidos.
• `transaction:created`, `transaction:updated`, `transaction:deleted`: Disparados no financeiro.
• `data:changed`: Evento genérico com `{type, action}` informando frontends para revalidar caches.
